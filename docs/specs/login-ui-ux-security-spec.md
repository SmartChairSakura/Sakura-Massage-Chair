# 📑 Master Specification & Security/UI Audit: Admin Login Flow (`/admin/login`)

> **Module:** Authentication & Access Control  
> **Target:** `src/app/admin/login/page.tsx` & `/api/admin/auth/*`  
> **Frameworks:** Next.js 14 App Router, React 18, Tailwind CSS, Lucide Icons, Jose (JWT)  
> **Disciplines Applied:** `/spec-driven-development`, `/frontend-ui-engineering`, `/security-and-hardening`  
> **Date:** 23 Oktober 2026

---

## 1. 🎯 Phase 1: Specification & Assumptions

### Assumptions Being Made:
1. Admin login is exclusively accessed via web browsers (Desktop & Tablet landscape priority).
2. Sessions are secured via HTTP-only, SameSite, Secure JWT cookies (`sakura_admin_token`) signed with a 24-hour expiration.
3. Legitimate administrators are stored in Supabase `admin_users` table with bcrypt-hashed passwords.
4. If SMTP credentials (`SMTP_USER`, `SMTP_PASS`) are not configured, OTP simulation must strictly be confined to secure server logs in development and **NEVER** leaked to client response payloads in production.
5. The design system must strictly adhere to the Sakura Zen palette (Primary `#795465`, Secondary `#4F4448`, Neutral `#FBF9F9`) with zero AI aesthetic cliches.

### Core Objectives:
- **Flawless Security:** Eliminate credential leaks, prevent OTP enumeration, remove hardcoded plaintext fallback passwords, and enforce rate-limiting.
- **Production UI/UX:** Fix WCAG 2.1 AA text contrast failures, introduce password show/hide toggles, ensure keyboard-navigable dialogs, and provide instant visual feedback.

## 2. 🛡️ STRIDE Threat Model (Login & Reset Boundary)

| Threat | Vulnerability / Attack Vector | Severity | Current Status in Code | Required Hardening Mitigation |
|---|---|:---:|---|---|
| **Spoofing** | Attacker impersonates admin by abusing hardcoded fallback credentials (`sakura123`, `admin123`, `parkee@1234`). | 🔴 **CRITICAL** | Line 65–75 of `login/route.ts` contains plaintext fallback credentials if Supabase query yields 0 rows. | **Remove all hardcoded credentials.** Enforce pure database verification against bcrypt hash with strict fallback denial. |
| **Information Disclosure** | Response body leaks reset OTP when SMTP is unconfigured (`devOtp` in JSON response). | 🔴 **CRITICAL** | Line 60 of `forgot-password/route.ts` returns `{ devOtp: otpCode }` directly to the browser. | **Strip `devOtp` completely from API response.** Only output to `console.log` in local `NODE_ENV !== 'production'`. |
| **Denial of Service & Brute Force** | Automated brute-force attacks against the 6-digit OTP (100,000–999,999) or admin passwords. | 🟠 **HIGH** | No rate-limiting or maximum attempt cap in `forgot-password` or `reset-password`. | Enforce maximum 5 attempts per OTP before invalidation + IP/Account rate limit (10 requests / 15 mins). |
| **Elevation of Privilege** | Serverless state loss: `otpStore = new Map()` lives in stateless Lambda memory. | 🟠 **HIGH** | `src/lib/otp-store.ts` uses in-memory Map. In multi-region Vercel Lambdas, Lambda B cannot verify OTP generated by Lambda A. | Persist OTPs into Supabase `admin_users` (e.g. `reset_otp_hash`, `reset_otp_expires_at`) or Redis/KV. |
| **Tampering** | Weak password confirmation check on client side without server-side complexity validation. | 🟡 **MEDIUM** | Password only requires `length >= 6` without symbol/number complexity rules. | Enforce minimum 8 characters with alphanumeric requirements via Zod schema validation. |

## 3. 🎨 Frontend UI/UX Audit & Accessibility (WCAG 2.1 AA)

### A. Critical Visual & Contrast Violations:
1. **Submit Button Contrast Failure (WCAG 1.4.3 Violation):**
   - **Current Code:** Line 261: `bg-gradient-to-r from-[#F8C8DC] to-[#795465] text-white`
   - **Issue:** `#F8C8DC` (Light Sakura Pink) paired with `#FFFFFF` text has a contrast ratio of only **1.45:1** (minimum required is **4.5:1**). The words *"Sign In"* are almost unreadable on the left half of the button.
   - **Fix:** Replace gradient with solid primary brand `#795465` (Plum) and hover `#684756`, which delivers a crisp **5.8:1** contrast ratio.

2. **Missing Password Visibility Toggle:**
   - **Issue:** Password fields on both the main login and reset modal lack a show/hide toggle (`Eye` / `EyeOff` icons). Users on mobile devices frequently mistype complex passwords without visual verification.
   - **Fix:** Add interactive eye toggle button inside the right padding of password inputs.

3. **Form Accessibility & Screen Reader Linkage:**
   - **Issue:** Labels currently use raw `<div>` and `<label>` without `htmlFor="email"` and matching `id="email"` on the inputs.
   - **Fix:** Link all labels with `htmlFor` and `id`, add `aria-describedby` for error banners, and add `aria-busy={isLoading}` on the form.

4. **Modal Accessibility & Focus Trap:**
   - **Issue:** The Forgot Password modal lacks `role="dialog"`, `aria-modal="true"`, and does not close on `Escape` key press.
   - **Fix:** Add keyboard `keydown` listener for `Escape`, implement focus trap on modal open, and add `aria-label="Close dialog"` on the close button.

## 4. 📐 Target Specification: Refined Login & Reset Flow

### Design System Tokens:
- **Primary Action:** `bg-[#795465] hover:bg-[#684756] text-white` (Solid Plum)
- **Input Background:** `bg-[#F5F3F3] border-[#EFEDED] focus:bg-white focus:border-[#795465]`
- **Error Banner:** `bg-[#FFDAD6] border-[#BA1A1A]/20 text-[#93000A]` (WCAG Compliant Alert)
- **Success Banner:** `bg-[#CEE5DA] border-[#4E635A]/20 text-[#4E635A]` (WCAG Compliant Success)

### Data Boundaries:
- **Always:** Use bcrypt salt rounds $\ge 12$, set HttpOnly/Secure/SameSite=Lax cookies, parameterize database queries.
- **Ask First:** Changing session cookie expiration (currently 24h), modifying RBAC roles.
- **Never:** Return `devOtp` or stack traces in HTTP JSON responses, store plaintext credentials, or allow password resets without OTP validation.
